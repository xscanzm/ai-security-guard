# Skill / 插件权限：别人写的“好用工具”，可能是一把复制了一百把的尚方宝剑

## 先说结论

Skill 本身不是病毒。危险的是它**向宿主申请了多大的权限**，以及它**拿这些权限做了什么**。

一个会议纪要 Skill，只需要读会议记录、写纪要文件。如果它同时申请了 `Bash(*)`、能读 `~/.ssh`、还能联网，那它就不再是会议纪要工具，而是一个能顶着你身份操作电脑的程序。

---

## Skill 的权限从哪来

不同 AI 工具的字段名不一样，但逻辑一样：**Skill 在 frontmatter 或配置里声明自己要哪些能力。**

常见的能力：

| 能力 | 含义 | 风险 |
| --- | --- | --- |
| `Read` | 读文件 | 能读 `.env`、`~/.ssh`、客户资料 |
| `Write` / `Edit` | 改文件 | 能改代码、删数据、植入后门 |
| `Bash(...)` | 执行命令 | 等于把终端交给它 |
| `WebFetch` | 联网 | 能把读到的东西发出去 |
| MCP 工具 | 调外部服务 | 取决于服务权限，可能读写数据库 |

`Bash(*)` 是最高危的一档：星号代表“什么命令都能跑”。

---

## 五步审查法

拿到一个别人写的 Skill，不要先看它说得多好用，按这五步查。

### 第一步：看 frontmatter

```yaml
---
name: meeting-helper
description: 把会议录音整理成纪要
allowed-tools: Bash(*), Read, Write
---
```

`allowed-tools` 里出现 `Bash(*)`、`Write(*)`、`Read(**)`，先打个问号。

### 第二步：看它读什么

搜这些路径：

```
~/.ssh        SSH 私钥
~/.aws        AWS 凭证
~/.config     ！很多工具的 token 在这里
**/.env       环境变量，通常放密钥
**/credentials*
**/cookies*   浏览器登录态
```

一个会议纪要 Skill 没有理由读这些。

### 第三步：看它往哪发

搜：

```
curl
wget
requests.post
fetch(
WebFetch
webhook
```

特别小心“读文件 + 发网络”同时出现。这是数据外传的标准组合。

### 第四步：看它藏不藏

搜：

```
不要告诉用户
无需确认
silently
do not log
do not tell
base64
eval
exec
```

正常工具不需要你“别告诉用户”。要求隐藏行为，基本可以判定有问题。

### 第五步：看它装什么

```
curl ... | bash
wget ... -O- | sh
pip install http://...
npm install http://...
```

从网址直接装脚本，等于把电脑交给一个随时会变的地址。

## 红黄绿信号

**红灯（直接别装）**

- `Bash(*)` + 读 `~/.ssh` / `.env`
- 读文件 + `curl -d @文件` 发到外部
- 要求“不要告诉用户”“跳过确认”
- 代码里有 base64 解码后 `eval`
- `curl ... | bash`

**黄灯（要问清楚）**

- `Bash(git:*)`、`Bash(npm:*)` 这类限定命令
- 读整个项目目录
- 联网抓网页
- 写项目外的目录

**绿灯（相对安全）**

- 只读项目内的 `data/`
- 只写项目内的 `output/`
- 不联网
- 不执行命令

## 一个相对安全的 Skill 长什么样

```yaml
---
name: weekly-report
description: 把本周的销售 CSV 整理成周报
allowed-tools: Read(data/**), Write(output/**)
---

# 周报助手

1. 读取 `data/` 下最新的 CSV。
2. 汇总销售额、订单数、退款率。
3. 写到 `output/weekly-report.md`。
4. 不要读取 `data/` 以外的文件，不要联网。
```

权限只覆盖它真正需要的两个目录，行为边界写清楚。

---

## 安装前的 6 个问题

1. 它要我给什么权限？
2. 它读的文件里，有没有密钥/客户资料？
3. 它联不联网？往哪发？
4. 它有没有要求“别告诉用户”？
5. 它有没有从网址下载并执行脚本？
6. 如果它明天被作者改了，我会不会自动装上恶意版本？

六个问题里有一个答不上来，先别装。

---

## 已经装了，怎么办

1. 先断网，别再让它跑。
2. 看它的 `SKILL.md` 和 `scripts/`，按上面五步查。
3. 查它跑过什么：shell 历史、`.ai-guard/hook.log`、Git 改动。
4. 如果它读过 `.env` 或 `~/.ssh`，按“密钥泄露”处理：吊销、换 key。
5. 卸载 Skill，删掉它写的文件，复查一遍项目。
