# 文档隐私：最贵的泄密，往往发生在“举个例子”的时候

## 先说结论

让 AI 写案例、模板、投标文件时，为了让例子“看着真实”，很多人会顺手把真客户的名字、电话、合同底价贴进去。文档生成后，又顺手分享到群里、网盘、公网。

**AI 不会替你判断哪个字段敏感。它只会把你说过的话，写进一份更容易被转发的文件里。**

---

## 哪些东西不能当例子

| 类型 | 例子 | 风险 |
| --- | --- | --- |
| 姓名 | 王建国、李秀兰 | 能定位到具体的人 |
| 手机号 | 13812345678 | 能直接联系、能撞库 |
| 身份证 | 110101199003071233 | 能冒充、能开账号 |
| 银行卡 | 622202... | 能盗刷 |
| 邮箱 | wangjianguo@company.com | 能钓鱼、能撞库 |
| 地址 | 某市某区某路 88 号 3 单元 501 | 能定位 |
| 微信/QQ | wxid_xxx、12345678 | 能直接加人 |
| 合同金额 | 合同总价 128 万，底价 96 万 | 泄露报价体系 |
| 返点/佣金 | 返点 15% | 泄露渠道政策 |
| 工资 | 月薪 25K | 泄露薪酬体系 |
| 内部标记 | 机密、仅限内部、禁止外传 | 说明这份文件本身就不该外发 |

## 打码的正确姿势

打码不是把字涂黑，而是**保留格式，去掉原值**。

| 原值 | 错误打码 | 正确打码 |
| --- | --- | --- |
| 13812345678 | 138****5678（还能猜） | 138****0000（统一用占位） |
| 王建国 | 王**（结合公司能猜到） | 王某 / 客户 A |
| 110101199003071233 | 110101********1233 | 110101********0000 |
| 128 万 | 128 万（没打） | 约 130 万 / 七位数 |
| wangjianguo@x.com | w***@x.com | client-a@example.com |

原则：**打码后的值，不能反推出原值。**

## 合成数据怎么写

写案例、做模板时，直接用一套固定的假数据：

```
客户名：某连锁餐饮（华东区）
联系人：王女士
电话：13800138000
邮箱：client-a@example.com
身份证：110101199003071233（合成，校验位正确）
合同金额：约 120 万元
底价：不便透露
地址：某市某区某路 88 号
微信：demo-client-a
```

`13800138000` 是常见的示例号；`110101199003071233` 是合成身份证，校验位正确但不对应真人。**不要用真实客户的任何字段做“微调”。**

---

## 让 AI 写文档时，先把这句话贴进去

```text
请用合成数据写示例，不要使用任何真实客户信息。
姓名用“王某/客户 A”，电话用 13800138000，
邮箱用 client-a@example.com，身份证用 110101199003071233，
公司名用“某连锁餐饮”，金额用“约 120 万元”。
如果原文里有真实信息，先替换成占位符，再动笔。
```

## 文档外发前的 5 步

1. 搜手机号：`1[3-9]\d{9}`
2. 搜身份证：`\d{17}[\dXx]`
3. 搜邮箱：`[\w.+-]+@[\w-]+\.[\w.]+`
4. 搜金额/底价/返点：`底价|返点|佣金|合同金额|万`
5. 搜内部标记：`机密|内部|禁止外传|仅限`

五步都过了，再发。

---

## 已经发出去了，怎么办

1. **先撤回**：群消息、网盘、文档链接，能撤就撤。
2. **改权限**：把公开链接改成指定人可见。
3. **评估范围**：发出去了多久、被谁看过、有没有下载记录。
4. **通知相关人**：涉及客户信息的，按合同/法规要求通知。
5. **留记录**：时间、范围、处理动作，写下来。
6. **补流程**：下次外发前必须跑一遍 `guard.py scan . --domain doc`。

不要做的一件事：**不要为了掩盖，把记录删掉。** 出了事，记录是救你的，不是害你的。
